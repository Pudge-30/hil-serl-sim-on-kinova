# 摇杆归位检测问题修复

## 问题描述

使用手柄操作时，不能正常检测到摇杆归位，机械臂会持续朝一个方向运动。

## 根本原因

1. **事件驱动限制**：`inputs.get_gamepad()` 是事件驱动的，只有在摇杆移动时才会发送事件
2. **缺少归位检测**：当摇杆回到中心位置时，可能不会发送事件，或者发送的事件值不在死区内
3. **状态保持问题**：如果没有新事件，action值会保持之前的值，导致机械臂持续运动

## 修复方案

### 1. 增大死区阈值
- **修改前**：`deadzone = 0.01` (1%)
- **修改后**：`deadzone = 0.05` (5%)
- **原因**：更宽松的死区可以更好地识别摇杆中心位置，过滤硬件噪声

### 2. 立即重置机制
当收到的事件值在死区内时，立即将对应的action重置为0：
```python
is_in_deadzone = abs(normalized_value) < deadzone
if event.code == 'ABS_Y':
    action[0] = 0.0 if is_in_deadzone else scaled_value
```

### 3. 超时自动重置机制
添加了超时检查机制：
- **超时时间**：150ms
- **检查频率**：每100ms检查一次
- **逻辑**：如果某个轴超过150ms没有更新，且当前action值不为0，则自动重置为0

```python
if current_time - axis_last_update[axis_code] > axis_timeout:
    if abs(action[action_idx]) > 0.001:
        action[action_idx] = 0.0
```

### 4. 扳机特殊处理
扳机需要特殊处理，因为两个扳机共享同一个action[2]：
- 右扳机（ABS_RZ）：正值，向上移动
- 左扳机（ABS_Z）：负值，向下移动
- 当扳机回到中心时，只重置对应方向的action值

## 修复效果

1. **立即响应**：当摇杆回到中心并发送事件时，立即重置action值
2. **自动恢复**：即使没有收到归位事件，也会在150ms后自动重置
3. **防止漂移**：增大的死区可以更好地过滤硬件噪声和校准误差

## 测试建议

1. **测试摇杆归位**：
   - 推动摇杆，然后释放
   - 观察机械臂是否在150ms内停止运动

2. **测试死区**：
   - 轻微推动摇杆（不离开中心位置）
   - 观察机械臂是否不会移动

3. **测试所有轴**：
   - 左摇杆（X/Y平移）
   - 右摇杆（Roll/Pitch旋转）
   - 扳机（Z平移）
   - D-pad（Yaw旋转）

## 可调参数

如果需要调整行为，可以修改以下参数：

   ```

2. **超时时间**（第287行）：

   ```

   ```python
   if current_time - last_check_time > 0.1:  # 减小此值可以更频繁检查
   ```

## 注意事项

1. **扳机行为**：扳机的超时检查只重置对应方向的action值，不会影响另一个扳机
2. **性能影响**：定期检查会略微增加CPU使用，但影响很小（每100ms检查一次）
3. **事件丢失**：如果系统负载过高导致事件丢失，超时机制可以确保action最终会被重置
